QA at Artlist — Growth domain

July 2025 – July 2026. I owned QA for the Growth domain — the subscription, billing and upgrade funnels Yuval Bazilevich calls the team's most business-critical areas — in a QA team, combining dependable manual coverage with automation and tooling that made the whole team faster.

  • “He brings strong product knowledge across our platforms and a constructive, adaptable working approach.” — Vili Medina, Head of R&D, Growth, Artlist
  • Billing safety net

    Pricing-validation agent

    Problem: a wrong price in a subscription billing system is expensive and hard to see by eye. It usually surfaces when a customer pays it.

    What I built: an autonomous agent, written in TypeScript, that checks live pricing against the billing system across plans and rules and posts any discrepancy to Slack.

    Result: caught 2 billing misconfigurations before they reached production.

    • TypeScript
    • Chargebee
    • Slack alerts

    Described in Yuval Bazilevich's letter (Growth Team Lead).

  • AI product quality

    Testing AI agents in production

    Scope: two production AI agents — a generative prompt assistant inside the product, and a third-party AI support agent answering customers.

    What I did: tested both for accuracy, behaviour and edge cases, with billing questions and user identification as the hard cases. Ran the support agent against real tickets, labeled the answers it got wrong, compared it side by side with a general-purpose LLM on the same tickets, and drove fixes with the vendor.

    Why it matters: an AI agent fails politely. A confident wrong answer about a refund looks like a success in the logs.

    • LLM output evaluation
    • Labeled failure set
    • Vendor bug reports
  • Automation

    Playwright + CI end-to-end suites

    Scope: the user states the Growth team owned: visitor/guest, free-trial and upgrade journeys.

    What I did: maintained, extended and improved the Playwright end-to-end suites and their GitLab CI integration. Page Object Model, specs for orchestration and page objects for the details, so regressions fail at the gate instead of after release.

    Result: dependable automated coverage of the most business-critical funnels.

    • Playwright

  • Test design

    From ticket to test plan

    Problem: a new plan launch multiplies cases fast — every plan × model × checkout path × pricing-page tab — and gaps hide in the spec, not the code.

    What I did: set up a pipeline from Jira ticket, to gap analysis against the spec, to Gherkin cases in CSV, imported into Zephyr Scale — and wrote 44 test plans and coverage matrices (700+ rows): a new AI-generation plan launch, studio onboarding and credits UI, checkout and upgrade flows, exploratory charters.

    Result: test cases written and prioritised faster, in one consistent format.

    • BDD / Gherkin
    • Jira
    • Zephyr Scale

    The AI-assisted test-design tooling is described in Yuval Bazilevich's letter.

  • Test data

    On-demand test accounts

    Problem: subscription bugs depend on account state — trial, expired, upgraded, a specific plan — which is slow to reproduce by hand.

    What I built: automated generation of test accounts in the exact subscription state a scenario needs, plus a maintained list of 240 QA accounts mapped to plans and states.

    Result: subscription-specific scenarios reproducible on demand instead of by hand.

    Described in Yuval Bazilevich's letter.

    Funnel monitoring, alerts & triage

    What I built: analytics dashboards with automated Slack alerts on conversion-funnel drops, and runbooks that cross-reference Mixpanel, Datadog and Sentry to find the cause.

    Result: production behaviour became a QA signal; incidents owned through to closure.

    • Mixpanel

  • AI-assisted QA

    A skills library the QA team ran on

    Problem: knowledge of how to test a given flow stayed in people's heads, and writing cases from specs was slow, repetitive work.

    What I built: 49 agent skills in a dedicated QA monorepo — each a written procedure an AI assistant runs the same way every time — and an internal plugin the QA team adopted. The Growth cluster encodes the money paths: growth-add-plan, growth-add-country-vat, growth-validate, growth-debug-journey, toolkit-journey-coverage. Alongside them, review skills (review-code, validate-pr, audit) and planning skills that turn a ticket into a test plan.

    Result: a recurring bug class became a repeatable procedure instead of tribal knowledge.

    Described in Yuval Bazilevich's and Vili Medina's letters.

Before QA: Tier 2 support operations

Artlist, April 2024 – June 2025. Escalation point for the support floor across subscriptions, payments and technical faults on web, mobile, plugins and AI products; root cause first, then a reproducible report for engineering. Along the way I pushed for changes to how the floor itself worked.

  • Routing

    Subject routing for a ~1,000-ticket day

    Problem: after new AI products launched, volume reached about a thousand tickets a day on one or two shared inboxes. Tickets bounced between agents, and billing cases were reassigned by hand.

    What I did: pushed for a split by subject — the bot asks the customer for a subject, a tag attaches, the ticket lands in the matching inbox. Tier 1 kept the simple tickets; specialists stayed in theirs. Asked for agents to take a ticket before replying and own it A to Z. A long-waiting queue came later on top.

    Result: better answers and faster resolution. The SLA target went from 10 hours to 8 in that period.

    • Zendesk triggers & views
    • Bot flows
    • Tags
  • Incident flow

    War room → Zendesk + Jira

    Problem: urgent bugs lived in Slack threads; support, R&D and the ticket queue each had a different picture.

    What I did: helped set clear rules for what is a war room and what is a regular bug, then worked with DevOps on a Slack bot that opened the urgent bug in Jira and as a problem ticket in Zendesk at the same time.

    Result: one incident, one ID, visible to everyone who needed it.

    • Slack bot
    • Zendesk API
    • Jira
  • Voice of the user

    Feature requests into Jira

    Problem: feature requests died in the support queue as tickets to close.

    What I did: helped promote an extension that captured user ideas and feature requests so agents could open them as Jira tickets, and presented the user's voice to stakeholders.

    Result: Product saw the request instead of a closed ticket.

    A Claude plugin and MCP server that analyses recordings: chords, notes, groove and form. The QA part is the discipline around it: accuracy is scored against reference transcriptions (note-level F1), benchmarks are leakage-controlled, and every report reads unmeasured until a real score exists.

  • Support tooling

    Zendesk Lab — a broken instance to fix

    A local practice instance that behaves like Zendesk Support and Admin Center, seeded with realistic breakage: a trigger that clears the assignee after a reply, tags nothing routes, no shared views. Five tasks fix it: routing, views, stay-assigned, a long-wait automation, and a war-room API call. It has its own automated tests.

    • Triggers & automations
    • Ticket API
    • Automated tests
  • Agent guardrails

    A personal agent with hard limits

    A personal assistant agent built from custom Claude skills, with rules it cannot cross: messages are drafts only, nothing is permanently deleted, and CV facts are locked to a verified list. A daily job-board scan lands as a draft digest, never a sent email. Designing those limits, and testing that they hold, is AI-agent QA applied to my own tools.
